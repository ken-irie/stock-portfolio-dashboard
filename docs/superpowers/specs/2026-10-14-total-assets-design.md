# 資産全体表示の設計 — 月次資産Excelの取り込みとCSVとの合算

作成日: 2026-10-14
ブランチ: `feat-total-assets`（`feat-chart-tap-detail` から分岐。スマホのタップ詳細の操作感にそろえるため）

## 1. 背景と目的

今のアプリが表示しているのは、証券会社のCSVから読んだ**証券口座の中の資産だけ**である。預金・仮想通貨・企業DC・電子マネーなどは、ユーザーが手元のExcel（`入江健太.Co 収支.xlsx` の「〇〇〇〇年度　資産」シート）に毎月末に記入している。

このExcelをページで読み込み、CSVで足りない分をExcelで補って**資産全体とその月次推移**を表示する。

### 運用の前提

| データ | 頻度 | 内容 |
|---|---|---|
| CSV | 気になったときに都度 | 楽天証券・SBI証券の保有明細（株・投信・債券・外貨預り金） |
| Excel | 月末に記入 | 証券口座以外も含めた全資産。1シート＝1年度（3月〜翌3月） |

**方針：CSVで取れるものはCSVを優先し、CSVにないものだけExcelで補う。**

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 取り込み方 | ページで .xlsx を選んで読み込み、Supabaseに保存する |
| 保存する形 | Excelの元の行（記録日・種類・項目・金額）をそのまま保存し、CSVとの合算は表示時に行う |
| 対象年度 | 2022〜2026年度の全シート |
| CSVとの合わせ方 | 月ごとに合算（推移は月1点） |
| 画面 | ページ最上部に新セクション「資産全体」を追加。既存の表示はそのまま |
| xlsx解析 | SheetJS（xlsx）を1本追加する。ビルド不要は維持 |

## 3. Excelの読み取り

### 3.1 シートの構造（実ファイルで確認済み）

- シート名：`2022年度　資産` 〜 `2026年度　資産`（`2023年度　資産 ` は末尾に空白あり）。他に `Sheet1` や収支シートがある
- 「種類」「資産」と書かれた見出し行があり、その右に月（`３月` `４月` … または `現在`）が並ぶ
- 見出し行の**すぐ上の行**に、各月の記録日（datetime）が入っている
- 2022・2023年度は列が1つ右にずれている（B列が空でなく A列に「実際」などがある）
- 種類は先頭行にだけ書かれ、以降は空欄
- 最後に「合計」行、その下に「今月-先月」行。2022年度はさらに下に「理想」の表がある
- 月の右に「合計（実際）」などの集計列がある
- 未記入の月は記録日・金額とも空

### 3.2 読み取りルール

1. シート名が `/^\d{4}年度\s*資産\s*$/` に一致するシートだけを読む
2. 「種類」と「資産」が隣り合うセルを探し、その行を見出し行とする（列位置は固定しない）
3. 見出し行の1つ上の行で、「資産」列より右にある**日付セル**を記録日とする。日付のない列は読まない（「合計（実際）」などの集計列や未記入月が除外される）
4. 見出し行の次の行から、種類列が「合計」になる行の手前まで読む
5. 種類が空欄なら直前の種類を引き継ぐ
6. 項目名は前後の空白を落とす（`Amazon ` → `Amazon`）
7. 金額が空・数値でないセルは保存しない（0は保存する）
8. 同じ記録日が複数シートにある場合は、**新しい年度のシートの値だけを使う**（例：2026/3/29 は2025年度末と2026年度初めの両方にあり、2026年度のほうに `日本円` の行が増えている）

### 3.3 出力

```js
[{ date:"2026-09-29", kind:"口座預金", item:"SBI証券", amount:1024212 }, ...]
```

記録日は `YYYY-MM-DD` 文字列にする。Excelの日付はタイムゾーンの影響を受けないよう、年月日を取り出して組み立てる。

## 4. 保存

### 4.1 テーブル

```sql
create table monthly_assets (
  record_date date    not null,
  kind        text    not null,
  item        text    not null,
  amount      numeric not null,
  primary key (record_date, kind, item)
);

alter table monthly_assets enable row level security;
create policy "anon all" on monthly_assets for all to anon using (true) with check (true);
```

RLSの方針は既存の `snapshots` / `holdings` と同じ（anonに全許可のポリシーを明示的に張る）。

### 4.2 保存の流れ

- 読み込むたびに**全件入れ替え**（全行DELETE → INSERT）。ブックに全年度が入っているので、まるごと置き換えるのが最も単純で、Excelから消した行がDBに残らない
- DELETE成功後にINSERTが失敗するとDBが空になるが、localStorageのキャッシュは残り、Excelを読み込み直せば回復する。これを許容する
- 既存の推移と同じく、localStorage（`kabu_monthly_assets_v1`）にもキャッシュし、起動時はSupabaseを正として読み戻す

### 4.3 `supabase.js` に追加する関数

例外を投げない方針は既存と同じ。

| 関数 | 戻り値 | 役割 |
|---|---|---|
| `sbSaveMonthlyAssets(rows)` | `Promise<boolean>` | 全件入れ替えで保存 |
| `sbLoadMonthlyAssets()` | `Promise<Array\|null>` | `[{date, kind, item, amount}]` を返す。失敗時は `null` |
| `sbLoadBrokerTotals()` | `Promise<Array\|null>` | CSVの日ごと・証券会社ごとの合計と外貨預り金。`[{date, broker, total, usdCash}]` |

`sbLoadBrokerTotals()` は `holdings` から `snapshot_date,broker,code,value` を1回で取得し、ブラウザで集計する（外貨預り金は `code === "現金"` の行）。

### 4.4 公開版（Cloudflare Workers）

`worker/worker.js` の中継許可 `TABLE_PATH` に `monthly_assets` を追加する。

## 5. 合算のルール

Excelの記録日ごとに、次の手順で資産全体を計算する。純粋関数 `combineMonthly(excelRows, brokerTotals)` として実装する。

### 5.1 組み合わせるCSVを選ぶ

- 記録日 D について、**前の記録日より後〜D（含む）**に取り込んだCSVの日のうち、最も新しい日を使う
  - 最初の記録日は「D以前すべて」ではなく、D の31日前より後に限定する（古いCSVでExcelの値を上書きしないため）
- 範囲内にCSVがなければ、その月はExcelの値をそのまま使う

### 5.2 証券会社ごとに置き換える

選んだCSVの日に含まれる証券会社ごとに判定する。

| Excelの行 | 判定 | その日のCSVに楽天がある | その日のCSVにSBIがある |
|---|---|---|---|
| 楽天の証券 | 種類が「株式」かつ項目に「楽天」を含む | 楽天CSVの合計に置き換え | － |
| SBIの証券 | 種類が「株式」または「債権」かつ項目に「SBI」を含む | － | SBI CSVの合計（株・投信・債券・外貨預り金）に置き換え |
| SBIの預金 | 種類が預金系（5.3）かつ項目に「SBI」を含む | － | Excelの額 − SBI CSVの外貨預り金 |
| それ以外 | － | Excelのまま | Excelのまま |

- 「置き換え」は、該当するExcelの行をすべて0として扱い、CSVの合計を1つ足す（`SBI証券(日本株・NISA)` と `SBI証券(米国株)` のように複数行あっても二重にならない）
- 楽天CSVの外貨預り金は差し引かない（Excelの「株式 / 楽天証券」にその分も含めて記入している前提。ユーザー確認済み）
- SBI預金の差し引き結果が負になった場合も、0に切り上げずに負のまま計算する（CSVとExcelの日付差による一時的なずれで、合計を正しく保つため）

### 5.3 表示カテゴリ

| 表示カテゴリ | キー | 含まれるもの |
|---|---|---|
| 証券 | `securities` | CSVで置き換えた額、または楽天・SBIの株式・債権の行 |
| 企業DC・持株 | `pension` | 種類「株式」のうち上記以外（企業DC、持株） |
| 預金 | `deposit` | 種類が「口座預金」「口座」「証券口座」「銀行貯金」 |
| 仮想通貨 | `crypto` | 種類「仮想通貨」 |
| 現金・電子マネー | `cash` | 種類「現金」「電子マネー」 |

上記に当てはまらない種類は `deposit` ではなく、新たに「その他」としてまとめる（将来Excelに種類が増えても合計が狂わないように）。

### 5.4 出力

```js
[{ date:"2026-09-29", total:25569183,
   cats:{ securities:…, pension:…, deposit:…, crypto:…, cash:…, other:… },
   csvDate:"2026-09-15" /* 置き換えに使ったCSVの日。なければ null */ }, ...]
```

記録日の昇順。

## 6. 画面

### 6.1 配置

ページ最上部、「保有資産」セクションの上に新セクション「資産全体」を追加する。ツールバーに「資産Excel」ボタン（`accept=".xlsx"`）を追加する。

### 6.2 構成

- **総資産カード**：最新月の合計、前月比（金額と％）、記録日
- **月次推移**：カテゴリ別の積み上げ棒グラフ（SVG）。期間は 1年／3年／全期間（初期は1年）
  - PCはホバー、スマホはタップで、その月のカテゴリ別金額・合計・使ったCSVの日を表示する（`feat-chart-tap-detail` の操作感にそろえる）
  - CSVで置き換えた月は棒の下に小さな印を付ける
- **内訳**：最新月のカテゴリ別構成比を、横長の帯グラフと金額一覧で表示する
- 色・フォントは既存の黒×ゴールドのデザイントークンに合わせる。スマホ幅でも横スクロールが出ないこと

### 6.3 データがないとき・失敗したとき

| 状況 | 表示 |
|---|---|
| Excel未読み込み | 「資産Excelを読み込むと、預金なども含めた資産全体を表示します」 |
| 対象シートがない | 「『〇〇〇〇年度　資産』シートが見つかりませんでした」。保存済みデータは消さない |
| xlsxとして開けない | 「Excelファイルを読み込めませんでした」 |
| Supabase保存失敗 | 既存と同じ「DB同期失敗」。画面には読み込んだ内容を表示し、localStorageには保存する |
| 読み込み成功 | 「5年度分・55か月を取り込みました」のように年度数と月数を表示 |

## 8. テスト

**単体テスト（`test/assets.test.html`、既存の `test/supabase.test.html` と同じ方式）**

- 読み取り：見出し行の列ずれ（2022・2023年度型）、種類の引き継ぎ、空欄セル、日付のない列の除外、「合計」行での停止、重なる記録日で新しい年度を優先
- 合算：月の範囲内のCSVだけを使う、範囲外のCSVは無視、楽天だけ／SBIだけの日、SBI預金から外貨預り金を引く、SBIの株式行が複数あっても二重計上しない、カテゴリ分類、未知の種類は「その他」

**動作確認**

- 実際の `入江健太.Co 収支.xlsx` を読み込み、CSVのない月の合計がExcelの「合計」行と一致することを確認する
- PC幅・スマホ幅で表示とタップ詳細を確認する
